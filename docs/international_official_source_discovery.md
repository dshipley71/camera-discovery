# International official-source discovery and dorking policy

This repository keeps the public-camera discovery workflow location-agnostic.  International behavior is implemented as search hints, not as hard-coded target logic.  Target resolution, scope validation, trust decisions, and artifact writing remain downstream deterministic gates.

## Implemented

- Country/language-aware official-source query expansion in `camera_discovery.discovery.official_source_queries`.
- Search profiles in `camera_discovery.discovery.locations` for country code, ccTLD, official-domain, and localized public-camera terms.
- Mexico test coverage for `.gob.mx` / `.mx` plus Spanish terms such as `cámaras en vivo`, `cámaras viales`, `cámaras de tráfico`, and `monitoreo vial`.
- Ukraine test coverage for `.gov.ua` / `.ua` plus Ukrainian terms such as `камери онлайн`, `вебкамери`, and `камери дорожнього руху`.
- Generic country-code fallback using ISO alpha-2 codes for ccTLD-oriented source discovery.
- Harvest logging for `logs/google_dorking_summary.json` so notebook checks do not silently report missing dorking diagnostics.

## Integrated from the official public-source query list

The official query document is represented as curated templates for:

- general public/live camera pages;
- traffic / transportation / 511 pages;
- weather, airport, beach, harbor, park, mountain, campus, city, construction, public-safety, and tourism camera pages;
- safe exclusion filters for blocked internet-asset search indexes.

These queries are used as source-discovery seeds. They are not trusted camera records by themselves.

## Not integrated from the raw Google dork list

The raw dork list contains many direct device-interface fingerprints such as vendor titles, `axis-cgi`, login pages, default/password terms, and direct camera UI paths. Those are intentionally not integrated into default discovery or harvest behavior.

Reasons:

- They can target exposed devices instead of curated public-facing camera pages.
- They may surface login/admin/default-credential interfaces.
- They are not appropriate for source-discovery of official public camera inventories.

Only safe official-source dorks are generated by the application: `site:` / `filetype:json` / `filetype:geojson` queries against allowed public-source domains and country-aware official domains, with blocked-source exclusions.

## Mexico all-media test use case

Mexico is a test case, not a special workflow. A notebook can search all media with:

```bash
camera-discovery harvest-urls "Mexico City, Mexico public cameras" \
  --media all \
  --discovery-mode both \
  --image-asset-filter raw
```

The normal validation run still performs target resolution, scope checks, validation, trust separation, and output writing. The all-media harvest is intentionally broad and should not be treated as trusted output.
